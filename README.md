# 감염관리 실태조사 관리 시스템

의료기관 감염관리 실태조사의 **자료 입력 → 검증 → 결과 공표 → 의료기관 확인** 흐름을 한곳에서 관리하는 웹 앱입니다.
조사관이 의료기관별 조사 자료를 입력하고, 관리자가 검증해 회차별로 결과를 공표하며, 의료기관은 본인 기관의 결과를 확인합니다.

> **개발 중인 버전입니다.** 교육 과정의 결과물로, 아래 "구현 현황"의 기능까지 동작합니다.
> 입력·검증·공표 기능은 아직 만들지 않았습니다. 진행 상황과 남은 작업은 [CHECK.md](CHECK.md)에 있습니다.

## 누가 무엇을 하나

| 사용자 | 하는 일 |
|---|---|
| 누구나 (로그인 없음) | 실태조사 정의, 공표된 회차별 결과(공표일·참여율·기관 종별 추정치)와 지난 회차 이력을 봅니다. |
| 조사관 | 배정된 의료기관의 조사 자료를 입력하고 제출합니다. (계정은 관리자가 발급) |
| 관리자 | 회차·기관을 관리하고, 가입 신청을 승인하며, 결과를 검증해 공개합니다. |
| 의료기관 | 가입 신청 후 관리자 승인을 받으면, 본인 기관의 결과와 관리자 코멘트를 봅니다. |

공표된 결과는 누구나 볼 수 있지만, **기관별 개별 결과는 해당 기관만** 볼 수 있습니다. 응답 기관이 5곳 미만인 구간은 숨기고 전체 합계는 표시하지 않습니다.

## 구현 현황

- [x] 저장소(Supabase) 연결과 데이터 구조, 접근 규칙(행 단위 보안, 상태 규칙, 이력)
- [x] 공통 화면 틀과 디자인
- [x] 로그인 없이 보는 공개 첫 화면 (정의·개요·주요내용·주요결과, 회차별 공표 내역)
- [x] 이메일 로그인(의료기관용·조사관용·관리자용), 역할별 접근 차단, 비밀번호 재설정
- [x] 의료기관 회원가입, 관리자 가입 승인·교체 승인·거절, 계정 변경 이력
- [ ] 조사 회차 관리, 조사 대상·배정, 조사 자료 입력·검증·제출
- [ ] 추정치 산출, 결과 검증·공개·철회, 의료기관 대시보드

자세한 계획은 [PLAN.md](PLAN.md)를 보세요.

## 직접 실행하기

1. 의존 패키지를 설치합니다.

   ```bash
   npm install
   ```

2. Supabase 프로젝트를 만들고 `supabase/migrations/`의 파일을 순서대로 적용합니다. (Supabase CLI: `npx supabase db push`)

3. 프로젝트 루트에 `.env.local`을 만들고 아래 값을 넣습니다. 값은 Supabase 대시보드에 있으며, **이 파일은 저장소에 올리지 않습니다.**

   ```
   NEXT_PUBLIC_SUPABASE_URL=         # 프로젝트 주소
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=   # 공개 키 (브라우저에 노출되어도 되는 값)
   SUPABASE_SECRET_KEY=              # 비밀 키 (서버에서만 사용, 절대 노출 금지)
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

4. 개발 서버를 켭니다.

   ```bash
   npm run dev
   ```

   http://localhost:3000 에서 확인합니다.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `npm run dev` / `build` / `start` | 개발 서버 / 빌드 / 운영 서버 |
| `npm run lint` | 코드 검사 |
| `npm run check:db` | 저장소 연결 확인 |
| `npm run check:schema` | 데이터 구조·접근 규칙 점검 (임시 자료는 되돌려짐) |
| `npm run check:auth` | 로그인·역할별 접근 점검 (앱 서버 필요) |
| `npm run check:public` | 공개 첫 화면과 로그인 전 접근 범위 점검 (앱 서버 필요) |
| `npm run check:signup` | 회원가입·승인 점검 |
| `npm run check:secrets` | 비밀 값이 코드·빌드 결과·커밋 이력에 없는지 점검 |

## 보안 원칙

- 키와 토큰은 `.env`, `.env.local`에만 두며 저장소에 올리지 않습니다.
- 권한은 서버가 결정하고(화면에서 숨기는 것으로 막지 않음), 저장소에도 행 단위 접근 규칙을 둡니다.
- 비밀 키(전체 권한) 연결은 서버 코드에서만 쓰고 브라우저로 넘기지 않습니다.
